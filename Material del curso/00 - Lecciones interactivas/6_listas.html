// explicación detallada

La teoría, para alguien que arranca ahora

El TAD Lista: interfaz primero

Antes de escribir un solo puntero, esto es lo único que Bárbara necesita conocer para usar una lista:

lista_crear()crea una lista vacía
lista_destruir(l)libera toda la lista
lista_es_vacia(l)true si no tiene elementos
lista_insertar_comienzo(l, dato)agrega al principio
lista_insertar_final(l, dato)agrega al final
lista_extraer_primero(l)saca y devuelve el primero
lista_extraer_ultimo(l)saca y devuelve el último
lista_buscar(l, dato, cmp)busca un elemento
lista_borrar(l, dato, cmp)busca y elimina
lista_recorrer(l, visitar)aplica una función a cada dato

Ninguna de estas primitivas dice cómo está armada la lista por dentro. Esa es la parte de Alan.

El nodo: la pieza que arma todo

Por dentro, una lista simplemente enlazada es una cadena de nodos, donde cada uno conoce al siguiente:

struct nodo { struct nodo* next; // dirección del siguiente nodo void* data; // el dato que guarda este nodo };

La lista en sí solo necesita guardar un puntero al primer nodo — la cabeza. A partir de ahí, cada nodo te lleva al siguiente hasta llegar a uno cuyo next es NULL: ese es el final.

Insertar y extraer al comienzo

Insertar al comienzo es la operación más barata de todas: creás el nodo nuevo, le apuntás el next a la vieja cabeza, y movés la cabeza al nodo nuevo. No importa si la lista tiene 3 elementos o 3 millones — siempre son 2 punteros para actualizar. Por eso es O(1).

Insertar y extraer al final

Acá está el primer trade-off real: si la lista solo guarda un puntero a la cabeza, insertar al final significa recorrerla entera hasta encontrar el último nodo — O(n). Si además guardás un puntero al último nodo, insertar al final vuelve a ser O(1) — pero ahora tenés que mantener ese puntero actualizado en cada operación que pueda cambiar cuál es el último.

Doblemente enlazada: el precio y el premio

Una lista doblemente enlazada agrega un segundo puntero a cada nodo:

struct nodo { struct nodo* next; // el siguiente struct nodo* prev; // el anterior — lo nuevo void* data; };

El premio: borrar o insertar un nodo del que ya tenés la dirección se vuelve trivial, sin tener que recorrer nada para encontrar al anterior:

void remove(Nodo* aBorrar) { aBorrar->next->prev = aBorrar->prev; aBorrar->prev->next = aBorrar->next; delete aBorrar; }

El precio: un puntero extra por nodo (más memoria), y la obligación de mantener next y prev siempre consistentes — si te olvidás de actualizar uno de los dos, la lista queda rota aunque "compile perfecto".

Iteradores: recorrer sin conocer la implementación

Igual que con cualquier TAD, Bárbara nunca debería tocar el campo next de un nodo directamente. Para eso existe el TAD iterador, con sus propias primitivas: lista_iterador_crear, lista_iterador_actual, lista_iterador_siguiente, lista_iterador_termino. Con eso alcanza para recorrer cualquier lista, sin importar cómo esté implementada por dentro:

lista_iterador_t* it; for (it = lista_iterador_crear(l); !lista_iterador_termino(it); lista_iterador_siguiente(it)) { void* dato = lista_iterador_actual(it); // hacer algo con dato } lista_iterador_destruir(it);
