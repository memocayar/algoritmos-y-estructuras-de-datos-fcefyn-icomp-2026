// explicación detallada

La teoría, para alguien que arranca ahora

¿Por qué no alcanza con un ABB o un AVL?

En memoria, comparar una clave cuesta casi nada. En disco, lo caro es traer una página (un bloque de unos pocos KB): una vez que la tenés en memoria, mirar cientos de claves adentro es prácticamente gratis. Entonces conviene que cada nodo sea una página con muchas claves, para que cada lectura descarte casi todo el resto.

Un árbol con m hijos por nodo tiene altura de unos ⌈logm(n)⌉ niveles, y cada nivel es una lectura de disco:

hijos por nodo (m)niveles para 5.000.000 de clavescomentario

16≈ 6
100≈ 4un nodo = una página de unos pocos KB
500≈ 3la raíz y el primer nivel suelen quedar en memoria

¿Qué es un B+?

Es un árbol de búsqueda con muchos hijos por nodo, con dos ideas que lo distinguen del árbol B clásico: todas las claves reales viven en las hojas, y las hojas están enlazadas de menor a mayor. Los nodos internos no guardan datos: solo separadores, carteles que dicen "por acá bajá si buscás algo menor / mayor o igual".

palabraqué es
claveel dato que se guarda y se busca (por ejemplo, el nombre de un diagrama).
hojanodo del último nivel. Acá están TODAS las claves, ordenadas, y un puntero next a la hoja siguiente.
nodo internonodo que no guarda datos: solo separadores e hijos. También se lo llama "índice".
separadorclave de un nodo interno que reparte a los hijos: a la izquierda lo menor, a la derecha lo mayor o igual.
orden mmáximo de hijos de un nodo interno (en el código, Order). Con m = 3 los ejemplos entran en pantalla.
ANATOMÍA · m = 3 · claves 10, 20, ..., 70
nodo índice (solo separadores)hoja (los datos)next

Los separadores 30, 50 y 70 aparecen también en las hojas: en el B+ son copias. Las hojas forman una lista enlazada ordenada.

Las reglas (con m = Order)

  • Todas las claves están en las hojas, ordenadas. Una hoja guarda entre m/2 y m − 1 claves (la raíz puede tener menos).
  • Un nodo interno tiene entre (m+1)/2 y m hijos, y un separador menos que hijos (la raíz, desde 2 hijos).
  • Cada separador es una cota: lo de su izquierda es menor y lo de su derecha es mayor o igual.
  • Todas las hojas están a la misma profundidad: buscar cuesta siempre lo mismo.
  • Las hojas se enlazan con next, de menor a mayor.
  • Si una clave es igual a un separador, se baja por la derecha.

División entera: con m = 3 una hoja guarda 1 o 2 claves; con m = 4, entre 2 y 3. Otros autores (Berkeley) usan otro parámetro, d: fijate siempre si hablan de claves o de hijos.

Buscar

Se baja desde la raíz: en cada nodo interno se elige el hijo según los separadores, hasta llegar a una hoja, y ahí se busca la clave. Siempre se baja hasta la hoja, porque los datos solo están ahí (en el árbol B clásico podías cortar antes). Costo: una lectura por nivel.

Insertar

Se baja hasta la hoja que le toca y se inserta ordenada. Si la hoja llega a m claves, se parte en dos y le avisa al padre; si el padre llega a m+1 hijos, también se parte; si se parte la raíz, nace una raíz nueva y el árbol crece un nivel.

LA REGLA QUE DISTINGUE AL B+

Al partir una hoja, la primera clave de la hoja derecha se COPIA al padre: el dato tiene que seguir en la hoja. Al partir un nodo interno, la clave del medio SUBE y deja de estar abajo, porque ahí solo era un cartel. Copia en la hoja, subida en el interno.

Consultas por rango

"Todos los diagramas entre la A y la C": se baja una sola vez hasta la hoja de la clave inicial y se avanza por next hasta pasar la clave final. En un árbol B clásico habría que subir y bajar por el árbol una y otra vez. Costo: O(logF n + k), con k resultados.

Borrar

  1. Se baja hasta la hoja y se quita la clave. Si ya estaba ausente, no pasa nada.
  2. Si la hoja queda con menos del mínimo (underflow), lo arregla su padre mirando a los hermanos:
    • Préstamo: si un hermano tiene claves de sobra, se le pide una y se actualiza el separador del padre. No cambia la forma del árbol.
    • Fusión: si ningún hermano puede prestar, se unen los dos nodos y el padre pierde un separador y un hijo (es lo inverso de partir).
  3. La fusión puede dejar al padre en underflow: se repite hacia arriba. Si la raíz queda con un solo hijo, ese hijo pasa a ser la raíz.
UN DETALLE QUE SORPRENDE

Después de borrar, un separador puede quedar "viejo": ya no coincide con ninguna clave de las hojas. Es válido, porque el separador solo tiene que ser una cota (menor que lo de la derecha y mayor que lo de la izquierda). Por eso la regla es "separador = cota del hijo derecho", no "primera clave del hijo derecho".

El código, pieza por pieza

La clase completa (bPlusTree.hpp) tiene alta, baja, búsqueda y rangos, con la documentación de cada paso. Estas son las piezas que más enseñan.

El nodo. Un mismo tipo sirve para hojas e internos. children son dueños de sus hijos; pNext no es dueño, solo "mira" a la hoja siguiente.

/** @brief Nodo del árbol. Es un "contenedor de datos": por eso sus campos no llevan el prefijo m_. */ struct Node { explicit Node(const bool isLeaf) : leaf{ isLeaf } { } bool leaf; std::vector<TData> keys; ///< Hoja: las claves reales. Interno: los separadores. std::vector<Node*> children; ///< Solo internos. Dueños de los hijos. Node* pNext{ nullptr }; ///< Solo hojas. NO es dueño: apunta a la hoja de la derecha. };

Partir una hoja. La izquierda se queda con (n+1)/2 claves. El separador es una copia de la primera clave de la derecha, y las hojas se reenlazan.

/** * @brief Parte una hoja desbordada. La izquierda se queda con (n+1)/2 claves. * @details El separador es una COPIA de la primera clave de la hoja derecha: el dato sigue en la hoja. * Ej. m=3: [10,20,30] -> [10,20] y [30]; el separador es 30. */ static void splitLeaf(Node& leaf, Split& split) { const std::size_t leftCount{ (leaf.keys.size() + 1) / 2 }; auto* pRight{ new Node(true) }; // assign copia el rango [a, b) dentro de pRight->keys; erase lo quita de la hoja original. pRight->keys.assign(leaf.keys.begin() + leftCount, leaf.keys.end()); leaf.keys.erase(leaf.keys.begin() + leftCount, leaf.keys.end()); pRight->pNext = leaf.pNext; // la nueva hoja se engancha entre 'leaf' y su antigua siguiente leaf.pNext = pRight; split.separator = pRight->keys.front(); split.pRight = pRight; }

Fusionar dos hijos. Es el inverso de partir; la hoja izquierda hereda el pNext de la derecha y el nodo vaciado se libera con delete.

/** * @brief Fusiona el hijo 'leftIndex + 1' dentro del hijo 'leftIndex' (inverso de partir). * @details Hoja: se juntan las claves y la hoja izquierda hereda el pNext de la derecha (se saltea la que * desaparece). Interno: además BAJA el separador del padre, que queda en el medio. * Al final el padre pierde un separador y un hijo, y el nodo vaciado se libera con delete. */ void mergeWithRight(Node& parent, const std::size_t leftIndex) { Node& left{ *parent.children[leftIndex] }; Node* const pRight{ parent.children[leftIndex + 1] }; Node& right{ *pRight }; if (left.leaf) { left.pNext = right.pNext; } else { left.keys.emplace_back(parent.keys[leftIndex]); moveChildren(right.children, 0, left.children); } left.keys.insert(left.keys.end(), right.keys.begin(), right.keys.end()); parent.keys.erase(parent.keys.begin() + leftIndex); parent.children.erase(parent.children.begin() + leftIndex + 1); delete pRight; // el nodo derecho quedó fuera del padre y sin contenido: se libera }

Rango. Una bajada con findLeaf y después un bucle por pNext.

/** * @brief Claves entre low y high (ambas inclusive), en orden ascendente. * @details Se baja UNA sola vez hasta la hoja de 'low' y después se avanza por pNext. Esa es la * ventaja del B+: no hay que volver a subir al árbol para seguir en orden. */ std::vector<TData> range(const TData& low, const TData& high) const { std::vector<TData> result; if (!m_less(high, low)) // si el rango está invertido, no hay nada que buscar { bool passedHigh{ false }; for (const Node* pLeaf{ findLeaf(low) }; pLeaf != nullptr && !passedHigh; pLeaf = pLeaf->pNext) { for (const auto& key : pLeaf->keys) { passedHigh = passedHigh || m_less(high, key); // pasamos 'high': dejamos de agregar if (!passedHigh && !m_less(key, low)) { result.emplace_back(key); } } } } return result; }
