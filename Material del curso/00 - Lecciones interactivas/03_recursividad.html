// explicación detallada

La teoría, para alguien que arranca ahora

¿Qué es la recursividad?

Una función recursiva es una función que, para resolver un problema, se llama a sí misma para resolver una versión más chica del mismo problema. Es como esas muñecas rusas: para abrir la muñeca grande tenés que abrir la de adentro, y para esa, la de más adentro — hasta que llegás a la muñequita sólida que ya no se abre más. Esa muñequita sólida es el caso base.

Caso base y caso recursivo

Toda función recursiva necesita, sin excepción, dos partes:

  • Caso base: la condición más simple, que se resuelve directamente sin volver a llamarse. Sin esto, la función nunca para.
  • Caso recursivo: la función se llama a sí misma con una versión más chica o más simple del problema, acercándose al caso base en cada llamada.
REGLA PRÁCTICA

Si al escribir una recursión no podés señalar con el dedo "acá para" y "acá se achica el problema", todavía no está lista.

La pila de llamadas, en teoría

Cada vez que una función se llama a sí misma, el programa aparta un espacio nuevo — un marco de pila (stack frame) — para esa llamada puntual: sus parámetros, sus variables locales, y a dónde volver cuando termine. Esos marcos se apilan uno arriba del otro a medida que las llamadas se acumulan, y se sacan en orden inverso a medida que cada llamada termina y devuelve su resultado. Una recursión que nunca llega al caso base sigue apilando marcos hasta agotar la memoria disponible — eso es un stack overflow.

Recursividad y eficiencia

Una recursión puede tener caso base, terminar siempre, y aun así ser un problema: si dentro de cada llamada volvés a llamarte más de una vez con subproblemas que se superponen, terminás recalculando lo mismo una y otra vez. Eso no rompe el programa — lo hace exponencialmente más lento a medida que crece la entrada. Lo vas a ver en la galería de fallas.
