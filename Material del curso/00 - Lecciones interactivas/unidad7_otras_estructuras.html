La teoría, para alguien que arranca ahora

7.1 Tablas y funciones de dispersión

Una tabla de dispersión (hash table) es un arreglo de M casilleros donde cada clave tiene "su" casillero, calculado con una función de dispersión h(k) que devuelve un índice entre 0 y M − 1. Para buscar no se compara ni se recorre: se calcula h(k) y se mira ese casillero. Por eso, en promedio, buscar, insertar y borrar cuestan O(1).

EL TRATO

A cambio de esa velocidad, la tabla no guarda orden: no sirve para "el menor", "el siguiente" ni "todo entre A y C". Para eso están los árboles (por ejemplo el B+ del módulo anterior).

Qué hace buena a una función de dispersión

  • Determinista: la misma clave da siempre el mismo índice.
  • Rápida: se calcula en tiempo casi constante.
  • Uniforme: reparte las claves parejo entre los casilleros.
  • Usa toda la clave: si ignora parte de la clave, claves distintas chocan sin necesidad.

Para enteros, lo clásico es h(k) = k mod M, con M primo y no cercano a una potencia de 2. Para texto, una función polinomial que combine cada letra con su posición, como la de abajo. Sumar los códigos de las letras es una mala idea: los anagramas ("ROL", "LOR") dan el mismo valor (lo vas a ver en el laboratorio).

// Función de dispersión polinomial para texto: usa TODAS las letras y su posición. std::size_t hashString(const std::string& text, const std::size_t bucketCount) { constexpr std::uint32_t BASE{ 31 }; std::uint32_t hash{}; for (const char letter : text) { hash = hash * BASE + static_cast<unsigned char>(letter); // desborda a propósito (módulo 2^32) } return hash % bucketCount; }

Las colisiones son inevitables

Hay muchas más claves posibles que casilleros, así que dos claves distintas van a caer en el mismo casillero tarde o temprano (a eso se le dice colisión). Y pasa antes de lo que parece: con 365 casilleros, alcanzan 23 claves para que la probabilidad de al menos una colisión supere el 50% (la paradoja del cumpleaños). Entonces no se trata de evitarlas, sino de resolverlas.

Resolución 1: encadenamiento

Cada casillero guarda una lista con todas las claves que caen ahí. Insertar es agregar a la lista; buscar es calcular el casillero y recorrer su lista; borrar es sacar de la lista. Es simple, borrar es fácil, y la tabla sigue funcionando aunque tenga más claves que casilleros (el factor de carga puede pasar de 1).

class ChainedHashTable final { public: explicit ChainedHashTable(const std::size_t bucketCount) : m_buckets(bucketCount) {} bool insert(const int key) { std::list<int>& bucket{ m_buckets[indexOf(key)] }; const bool isNew{ std::find(bucket.begin(), bucket.end(), key) == bucket.end() }; if (isNew) { bucket.emplace_back(key); ++m_size; } return isNew; } double loadFactor() const noexcept { return static_cast<double>(m_size) / static_cast<double>(m_buckets.size()); } private: // El módulo de un negativo en C++ es negativo: se corrige para que el índice caiga en [0, M). std::size_t indexOf(const int key) const { const long long bucketCount{ static_cast<long long>(m_buckets.size()) }; return static_cast<std::size_t>(((key % bucketCount) + bucketCount) % bucketCount); } std::vector<std::list<int>> m_buckets; std::size_t m_size{}; };

Resolución 2: direccionamiento abierto

Todo vive dentro del arreglo, sin listas. Si el casillero h(k) está ocupado, se prueba otro siguiendo una secuencia fija, hasta encontrar un hueco. Las tres secuencias más conocidas:

métodocasillero que se prueba en el intento jcaracterística
sondeo lineal(h(k) + j) mod Mel más simple; forma "racimos" de casilleros ocupados que crecen (agrupamiento primario)
sondeo cuadrático(h(k) + j²) mod Mevita los racimos largos; con M primo y la tabla a lo sumo mitad llena, siempre encuentra lugar
doble hashing(h₁(k) + j·h₂(k)) mod Mel paso depende de la clave (acá, h₂(k) = 1 + k mod (M−1)); con M primo recorre todos los casilleros

Borrar es delicado. Si al borrar dejás el casillero vacío, cortás la cadena de sondeo de otras claves que pasaron por ahí, y una búsqueda posterior se detiene antes de tiempo. Por eso se marca el casillero como borrado (tombstone): la búsqueda sigue de largo, y una inserción puede reutilizarlo.

enum class SlotState { Empty, Used, Deleted }; struct Slot { SlotState state{ SlotState::Empty }; int key{}; }; class OpenHashTable final { public: static constexpr std::size_t NOT_FOUND{ static_cast<std::size_t>(-1) }; explicit OpenHashTable(const std::size_t slotCount) : m_slots(slotCount) {} // Sondeo lineal: prueba h, h+1, h+2, ... (módulo M) hasta encontrar la clave o un hueco NUNCA usado. std::size_t find(const int key) const { std::size_t result{ NOT_FOUND }; std::size_t index{ indexOf(key) }; for (std::size_t probes{}; probes < m_slots.size() && result == NOT_FOUND; ++probes) { const Slot& slot{ m_slots[index] }; if (slot.state == SlotState::Empty) { break; // si hubiera estado, habría quedado antes de este hueco } if (slot.state == SlotState::Used && slot.key == key) { result = index; } index = (index + 1) % m_slots.size(); } return result; } // Borrar NO deja el casillero vacío: lo marca como Deleted (tombstone) para no cortar la cadena de sondeo. bool erase(const int key) { const std::size_t index{ find(key) }; const bool found{ index != NOT_FOUND }; if (found) { m_slots[index].state = SlotState::Deleted; } return found; } private: std::size_t indexOf(const int key) const { const long long slotCount{ static_cast<long long>(m_slots.size()) }; return static_cast<std::size_t>(((key % slotCount) + slotCount) % slotCount); } std::vector<Slot> m_slots; };

Factor de carga y rehash

El factor de carga es α = n / M (claves guardadas sobre casilleros). Cuanto más alto, más colisiones. Con sondeo lineal, la cantidad esperada de casilleros que se revisan crece muy rápido cerca de 1:

αrevisados si la clave estárevisados si no está
0,51,52,5
0,752,58,5
0,95,550,5

Fórmulas de Knuth para sondeo lineal: ½(1 + 1/(1−α)) y ½(1 + 1/(1−α)²).

Cuando α supera un umbral (por ejemplo 0,7 en direccionamiento abierto, o 1 en encadenamiento) se hace un rehash: se crea una tabla más grande (alrededor del doble, con M primo) y se reinsertan todas las claves. No se pueden copiar tal cual, porque al cambiar M cambia el casillero de cada clave. Cuesta O(n), pero ocurre pocas veces: el costo amortizado por inserción sigue siendo O(1).

En la biblioteca estándar, std::unordered_map y std::unordered_set son tablas de dispersión (en la práctica, con encadenamiento) con rehash automático cuando el factor de carga pasa de max_load_factor() (por defecto 1,0).

7.2 Conjuntos y bolsas (sets y bags)

Un conjunto (set) es una colección de elementos sin repetidos y sin un orden que importe. Un bolsa (bag o multiconjunto) es lo mismo pero permite repetidos: no importa el orden, pero sí cuántas veces está cada elemento. Los dos son TADs: se definen por lo que hacen, no por cómo se guardan.

operaciónconjuntobolsa
agregaradd(x): si ya estaba, no pasa nadaadd(x): el contador de x sube en 1
quitarremove(x)removeOne(x): baja el contador en 1 (o removeAll)
consultarcontains(x): sí o nocount(x): cuántas veces
tamañosize()size() (total con repetidos) y distinct() (sin repetidos)
combinarunión ∪, intersección ∩, diferencia −, diferencia simétrica △suma (cuentas se suman), unión (máximo), intersección (mínimo), diferencia (resta, sin bajar de 0)

¿Cómo se implementan?

vector ordenadoO(log n)O(n) (hay que correr elementos)símuchas consultas, pocas altas

Una bolsa suele implementarse como un mapa de elemento a contador, o con std::multiset, que guarda cada copia. Las operaciones entre conjuntos de la STL (std::set_union, std::set_intersection, std::set_difference) trabajan sobre rangos ordenados y cuestan O(n + m), porque recorren los dos a la vez como en el merge de un merge sort.

// std::set guarda sin repetidos y ordenado. set_union necesita DOS rangos ORDENADOS y escribe el resultado // por un iterador de salida: inserter(resultado, ...) inserta cada elemento en el set resultado. std::set<int> unionOf(const std::set<int>& a, const std::set<int>& b) { std::set<int> result; std::set_union(a.begin(), a.end(), b.begin(), b.end(), std::inserter(result, result.end())); return result; } std::set<int> intersectionOf(const std::set<int>& a, const std::set<int>& b) { std::set<int> result; std::set_intersection(a.begin(), a.end(), b.begin(), b.end(), std::inserter(result, result.end())); return result; }
// Una bolsa (multiconjunto) guarda cuántas veces aparece cada elemento: elemento -> contador. class Bag final { public: void add(const std::string& item) { ++m_counts[item]; // operator[] crea el contador en 0 si no existe, y después lo incrementa } bool removeOne(const std::string& item) { const auto it{ m_counts.find(item) }; // find: O(log n); devuelve end() si no está const bool found{ it != m_counts.end() }; if (found && --it->second == 0) { m_counts.erase(it); // si no quedan copias, el elemento se elimina } return found; } std::size_t count(const std::string& item) const { const auto it{ m_counts.find(item) }; return it == m_counts.end() ? 0 : it->second; } std::size_t distinct() const noexcept { return m_counts.size(); } std::size_t size() const noexcept // total, contando repetidos { std::size_t total{}; for (const auto& entry : m_counts) { total += entry.second; } return total; } private: std::map<std::string, std::size_t> m_counts; };

7.3 Mapas de bits

Un mapa de bits (bitmap) guarda un bit por elemento: 1 significa "está / sí / ocupado" y 0 significa "no está / no / libre". Sirve cuando los elementos son enteros en un universo chico y denso (ids de 0 a 1.000.000, números de bloque de un disco, flags de permisos). Un millón de elementos ocupan 125.000 bytes, y no un millón.

El bit número i vive en el byte i / 8, en la posición i % 8, y se manipula con una máscara 1 << (i % 8):

operaciónen C++qué hace el operador
prender (set)byte |= maskOR: deja en 1 el bit de la máscara y no toca los demás
apagar (clear)byte &= ~maskAND con la máscara negada: pone en 0 solo ese bit
invertir (toggle)byte ^= maskXOR: si estaba en 1 pasa a 0 y viceversa
consultar (test)(byte & mask) != 0AND: queda distinto de 0 solo si ese bit está prendido
class Bitmap final { public: explicit Bitmap(const std::size_t bitCount) : m_bytes((bitCount + BITS_PER_BYTE - 1) / BITS_PER_BYTE, 0) {} void set(const std::size_t index) { m_bytes[index / BITS_PER_BYTE] |= maskOf(index); // OR: prende el bit } void clear(const std::size_t index) { m_bytes[index / BITS_PER_BYTE] &= static_cast<std::uint8_t>(~maskOf(index)); // AND con la máscara negada: apaga } void toggle(const std::size_t index) { m_bytes[index / BITS_PER_BYTE] ^= maskOf(index); // XOR: invierte } bool test(const std::size_t index) const { return (m_bytes[index / BITS_PER_BYTE] & maskOf(index)) != 0; // AND: ¿está prendido? } private: static constexpr std::size_t BITS_PER_BYTE{ 8 }; // Bit i vive en el byte i / 8, en la posición i % 8. 1u evita el desborde de un int con signo. static std::uint8_t maskOf(const std::size_t index) { return static_cast<std::uint8_t>(1u << (index % BITS_PER_BYTE)); } std::vector<std::uint8_t> m_bytes; };

Lo más lindo: las operaciones de conjuntos se vuelven operaciones sobre bytes (o palabras de 64 bits), que procesan muchos elementos a la vez. Unión = |, intersección = &, diferencia = a & ~b, diferencia simétrica = ^. Contar los bits prendidos (popcount) da el tamaño del conjunto.

Un ejemplo que ya usás: los permisos de Unix. chmod 755 son 9 bits: 111 101 101 = rwxr-xr-x (cada dígito octal agrupa 3 bits: r = 4, w = 2, x = 1). En la biblioteca estándar: std::bitset<N> (tamaño fijo en compilación) y std::vector<bool> (tamaño dinámico, empaquetado en bits).
