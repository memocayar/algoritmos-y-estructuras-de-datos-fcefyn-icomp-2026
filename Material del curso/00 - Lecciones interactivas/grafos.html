Representar la red: matriz, lista y CSR

La matriz de adyacencia es una tabla V × V: la celda [u][v] guarda el costo de la ruta u–v (o "no hay"). Consultar una arista es instantáneo, O(1), pero ocupa V² celdas aunque casi todas estén vacías. La lista de adyacencia guarda, para cada hub, solo sus vecinos: O(V + E) de memoria, y para probar una arista hay que recorrer los vecinos de un hub.

CSR (Compressed Sparse Row) es una lista de adyacencia sin un nodo enlazado por vecino: todas las listas van en un solo arreglo neighbor[] y rowStart[] indica dónde empieza la de cada hub. Los vecinos del hub u son neighbor[rowStart[u] .. rowStart[u+1] − 1] (intervalo semiabierto) y su grado es rowStart[u+1] − rowStart[u]. Se construye contando grados, haciendo sumas prefijas y colocando cada vecino. Es muy buena para redes grandes que se consultan mucho y casi no cambian; insertar una ruta obliga a desplazar datos o reconstruir.

// CSR: todas las listas de vecinos en un solo arreglo; rowStart[u]..rowStart[u+1]-1 son los vecinos de u. struct Csr { int rowStart[HUBS + 1]{}; int neighbor[2 * ROUTES]{}; int hours[2 * ROUTES]{}; }; void buildCsr(Csr& csr) { int fill[HUBS]{}; for (const Route& route : NETWORK) // 1) contar el grado de cada hub { ++csr.rowStart[route.from + 1]; ++csr.rowStart[route.to + 1]; } for (int hub{ 0 }; hub < HUBS; ++hub) // 2) sumas prefijas: inicio de cada fila { csr.rowStart[hub + 1] += csr.rowStart[hub]; } for (const Route& route : NETWORK) // 3) colocar cada vecino en su lugar { const int a{ csr.rowStart[route.from] + fill[route.from]++ }; const int b{ csr.rowStart[route.to] + fill[route.to]++ }; csr.neighbor[a] = route.to; csr.hours[a] = route.hours; csr.neighbor[b] = route.from; csr.hours[b] = route.hours; } }
// Matriz de adyacencia ponderada: hours[u][v] == INFINITE si no hay ruta directa. struct Matrix { int hours[HUBS][HUBS]{}; Matrix() { for (int u{ 0 }; u < HUBS; ++u) { for (int v{ 0 }; v < HUBS; ++v) { hours[u][v] = (u == v) ? 0 : INFINITE; } } for (const Route& route : NETWORK) { hours[route.from][route.to] = route.hours; hours[route.to][route.from] = route.hours; } } };

Explorar la red: BFS y DFS

Los dos recorren la red visitando cada hub una sola vez; cambia la estructura que guarda "lo pendiente". BFS usa una cola (FIFO): visita primero todo lo cercano, por ondas de distancia en tramos. Por eso encuentra el camino con menos tramos (no el de menos horas). DFS usa una pila (o la recursión): se interna por una rama hasta no poder más y retrocede. No garantiza el camino más corto, pero su árbol de exploración sirve para detectar ciclos, calcular tiempos de entrada y salida, y es la base de SCC y del orden topológico.

Un detalle que rompe programas: en BFS el hub se marca como visitado al encolarlo, no al desencolarlo. Para que las trazas sean reproducibles, los vecinos se recorren en orden alfabético. Con listas, los dos cuestan O(V + E); con matriz, O(V²).

// BFS: cola FIFO en un arreglo. Se marca al ENCOLAR para que ningún hub entre dos veces. void bfs(const Matrix& net, const int origin, int distance[HUBS]) { int queue[HUBS]{}; int head{ 0 }; int tail{ 0 }; for (int hub{ 0 }; hub < HUBS; ++hub) { distance[hub] = -1; } distance[origin] = 0; queue[tail++] = origin; while (head < tail) { const int current{ queue[head++] }; for (int next{ 0 }; next < HUBS; ++next) { const bool linked{ net.hours[current][next] != INFINITE && current != next }; if (linked && distance[next] < 0) { distance[next] = distance[current] + 1; queue[tail++] = next; } } } }
// DFS recursivo: la pila de llamadas hace de pila. Devuelve el orden de entrada. void dfs(const Matrix& net, const int current, bool visited[HUBS], int order[HUBS], int& count) { visited[current] = true; order[count++] = current; for (int next{ 0 }; next < HUBS; ++next) { const bool linked{ net.hours[current][next] != INFINITE && current != next }; if (linked && !visited[next]) { dfs(net, next, visited, order, count); } } }

Ruta más rápida: caminos mínimos

Ahora se minimiza la suma de pesos (horas), no la cantidad de tramos. La operación que une a todos los algoritmos es la relajación: si dist[u] + w(u,v) < dist[v], entonces mejoramos dist[v] y guardamos padre[v] = u. Una distancia tentativa es la mejor ruta encontrada hasta ahora, no necesariamente la óptima.

  • Dijkstra (una fuente, costos no negativos): en cada paso fija el hub no fijado con menor distancia tentativa y relaja sus rutas. Se puede fijar porque, sin costos negativos, ninguna ruta posterior puede mejorarlo. Con selección lineal cuesta O(V²); con un heap, O((V + E) log V).
  • Bellman-Ford (una fuente, admite costos negativos): relaja todas las aristas hasta V − 1 veces. Una pasada extra que todavía mejore revela un ciclo negativo alcanzable. Cuesta O(V·E). En grafos no dirigidos una arista negativa ya forma un ciclo negativo (ida y vuelta), por eso el ejemplo es de un solo sentido.
  • Floyd-Warshall (todos los pares): programación dinámica sobre dist[i][j], permitiendo de a un hub k como intermedio: min(dist[i][j], dist[i][k] + dist[k][j]). El orden de bucles k, i, j es fundamental. O(V³) tiempo, O(V²) memoria.

Otros que conviene conocer: caminos en un DAG (relajar en orden topológico: O(V + E), incluso con costos negativos), Johnson (Bellman-Ford para repesar las aristas y después Dijkstra desde cada origen: todos los pares en redes ralas) y A* (Dijkstra guiado por una heurística admisible hacia un destino).

// Dijkstra con selección lineal: O(V^2). Precondición: ninguna ruta con costo negativo. void dijkstra(const Matrix& net, const int origin, int distance[HUBS], int parent[HUBS]) { bool fixed[HUBS]{}; for (int hub{ 0 }; hub < HUBS; ++hub) { distance[hub] = INFINITE; parent[hub] = -1; } distance[origin] = 0; for (int round{ 0 }; round < HUBS; ++round) { int best{ -1 }; for (int hub{ 0 }; hub < HUBS; ++hub) { if (!fixed[hub] && distance[hub] != INFINITE && (best < 0 || distance[hub] < distance[best])) { best = hub; } } if (best < 0) { break; } fixed[best] = true; for (int next{ 0 }; next < HUBS; ++next) { const bool linked{ net.hours[best][next] != INFINITE }; const int candidate{ distance[best] + net.hours[best][next] }; if (!fixed[next] && linked && candidate < distance[next]) // relajación { distance[next] = candidate; parent[next] = best; } } } }

Conectar toda la red: árbol de expansión mínimo (MST)

Acá la pregunta es otra: conectar todos los hubs con el menor costo total. Un árbol de expansión tiene V − 1 aristas y ningún ciclo; el MST minimiza la suma de pesos. No minimiza el camino entre dos hubs en particular: en la red de DHL el MST cuesta 11 h en total y el camino más rápido de A a F cuesta 10 h, y no hay contradicción porque responden preguntas distintas.

Los dos algoritmos se justifican con la propiedad del corte: la arista más barata que cruza cualquier corte del grafo pertenece a algún MST (y, por la propiedad del ciclo, la más cara de un ciclo no hace falta).

  • Kruskal: ordena todas las rutas por costo y elige la siguiente solo si une dos grupos distintos (si no, cerraría un ciclo). Necesita saber rápido a qué grupo pertenece cada hub: eso lo da Union-Find.
  • Prim: arranca en un hub y hace crecer un único árbol: siempre agrega la ruta más barata que sale del árbol hacia un hub de afuera.
  • Union-Find (DSU): cada grupo tiene un representante; find busca la raíz y unite fusiona grupos. Con compresión de caminos y unión por tamaño, cada operación cuesta casi O(1) amortizado (O(α(V))). Sus enlaces padre son auxiliares: no son rutas de la red.
// Union-Find con compresión de caminos y unión por tamaño. struct DisjointSets { int parent[HUBS]{}; int size[HUBS]{}; DisjointSets() { for (int hub{ 0 }; hub < HUBS; ++hub) { parent[hub] = hub; size[hub] = 1; } } int find(const int hub) { if (parent[hub] != hub) { parent[hub] = find(parent[hub]); } return parent[hub]; } bool unite(const int a, const int b) { int rootA{ find(a) }; int rootB{ find(b) }; if (rootA == rootB) { return false; // ya están conectados: la ruta cerraría un ciclo } if (size[rootA] < size[rootB]) { const int swap{ rootA }; rootA = rootB; rootB = swap; } parent[rootB] = rootA; size[rootA] += size[rootB]; return true; } }; // Kruskal: ordenar las rutas por costo (inserción, estable) y elegir las que unen grupos distintos. int kruskal(Route chosen[HUBS - 1]) { Route sorted[ROUTES]{}; for (int i{ 0 }; i < ROUTES; ++i) { int j{ i }; while (j > 0 && sorted[j - 1].hours > NETWORK[i].hours) { sorted[j] = sorted[j - 1]; --j; } sorted[j] = NETWORK[i]; } DisjointSets groups; int total{ 0 }; int count{ 0 }; for (int i{ 0 }; i < ROUTES && count < HUBS - 1; ++i) { if (groups.unite(sorted[i].from, sorted[i].to)) { chosen[count++] = sorted[i]; total += sorted[i].hours; } } return total; }

Ida y vuelta: componentes fuertemente conexas (SCC)

Cuando hay rutas de un solo sentido (usamos A→B, B→C, C→A, B→D, D→E, E→D y F→E), poder llegar de B a D no implica poder volver. Una SCC es un conjunto maximal de hubs donde todos son mutuamente alcanzables. Acá son {A, B, C}, {D, E} y {F}. Una DFS simple no alcanza: hay que distinguir "ya visitado" de "ya pertenece a una componente cerrada".

  • Kosaraju: (1) DFS en el grafo original anotando el orden de finalización; (2) transponer el grafo (invertir las flechas); (3) DFS sobre el transpuesto arrancando por el que terminó último. Cada árbol de la segunda pasada es una SCC.
  • Tarjan: una sola DFS con disc[u] (orden de descubrimiento), low[u] (el descubrimiento más antiguo al que se llega) y una pila de hubs "abiertos". Si low[u] == disc[u], u es la raíz de una SCC y se desapila hasta u. Una arista a un hub que ya no está en la pila se ignora: ese es el detalle que impide mezclar componentes.
  • Condensación: si cada SCC se reduce a un vértice, el resultado es siempre un DAG (un ciclo entre componentes las fusionaría en una sola).
// Tarjan: una sola DFS con disc, low y una pila de hubs "abiertos". Red de UN solo sentido. struct OneWay { bool link[HUBS][HUBS]{}; int discovery[HUBS]{ -1, -1, -1, -1, -1, -1 }; int low[HUBS]{}; bool onStack[HUBS]{}; int stack[HUBS]{}; int top{ 0 }; int clock{ 0 }; int component[HUBS]{}; int componentCount{ 0 }; void visit(const int hub) { discovery[hub] = low[hub] = clock++; stack[top++] = hub; onStack[hub] = true; for (int next{ 0 }; next < HUBS; ++next) { if (!link[hub][next]) { continue; } if (discovery[next] < 0) { visit(next); low[hub] = (low[next] < low[hub]) ? low[next] : low[hub]; } else if (onStack[next]) // arista de retroceso dentro de la componente abierta { low[hub] = (discovery[next] < low[hub]) ? discovery[next] : low[hub]; } } if (low[hub] == discovery[hub]) // raíz de componente: se desapila hasta ella { int member{ -1 }; do { member = stack[--top]; onStack[member] = false; component[member] = componentCount; } while (member != hub); ++componentCount; } } };

El proceso de un paquete: DAG y orden topológico

Un paquete pasa por tareas que solo pueden empezar cuando otras terminaron. Es un grafo dirigido donde la arista u→v significa "u antes que v". Tiene solución si y solo si es un DAG (sin ciclos). Un orden topológico pone cada tarea después de todas sus previas; no es único (A, B, C, D, E, F y A, C, B, E, D, F sirven).

Para esta red: Recepción → Escaneo y pesaje, Recepción → Etiquetado, Escaneo → Despacho aduanero, Escaneo → Carga en camión, Etiquetado → Carga en camión, Despacho → Entrega, Carga → Entrega.

  • Kahn: lleva el grado de entrada de cada tarea (cuántas previas le faltan). Encola las de grado 0; al procesar una, resta 1 a sus sucesoras y encola las que llegan a 0. Si se vacía la cola y quedaron tareas sin procesar, hay un ciclo.
  • Por DFS: el orden inverso de finalización es un orden topológico, siempre que no se encuentre una arista a un hub "en proceso" (que sería un ciclo).
// Kahn: grados de entrada + cola. Devuelve cuántas tareas se pudieron ordenar (< HUBS ⇒ hay ciclo). int kahn(const bool depends[HUBS][HUBS], int order[HUBS]) { int pending[HUBS]{}; int queue[HUBS]{}; int head{ 0 }; int tail{ 0 }; for (int from{ 0 }; from < HUBS; ++from) { for (int to{ 0 }; to < HUBS; ++to) { if (depends[from][to]) { ++pending[to]; } } } for (int task{ 0 }; task < HUBS; ++task) { if (pending[task] == 0) { queue[tail++] = task; } } int done{ 0 }; while (head < tail) { const int task{ queue[head++] }; order[done++] = task; for (int next{ 0 }; next < HUBS; ++next) { if (depends[task][next] && --pending[next] == 0) { queue[tail++] = next; } } } return done; }

¿Cuánto soporta la red? Flujo máximo y asignaciones

Ahora cada ruta tiene una capacidad (paquetes por hora). Una asignación de flujo factible cumple 0 ≤ f(u,v) ≤ c(u,v) y la conservación: en cada hub intermedio, lo que entra es igual a lo que sale. Usamos una red nueva con los mismos hubs: S→A = 3, S→B = 2, A→B = 2, A→T = 2, B→T = 3 (S origen, T destino, A Córdoba, B Rosario).

Ford-Fulkerson busca caminos de S a T con capacidad libre en la red residual y los "aumenta". La red residual tiene, además de la capacidad que queda, una arista inversa con el flujo ya enviado: no es una ruta real de vuelta, sino la posibilidad de cancelar una decisión anterior. Edmonds-Karp es Ford-Fulkerson eligiendo siempre el camino con menos aristas (BFS): O(V·E²).

El teorema max-flow min-cut dice que el flujo máximo es igual a la capacidad del corte mínimo. Por eso, cuando no queda camino aumentante, el conjunto de hubs alcanzables desde S en la residual define un corte cuya capacidad es el flujo: eso certifica que es óptimo. De S pueden salir 3 + 2 = 5, lo que demuestra que nunca pueden llegar más de 5, pero no que lleguen 5.

Matching bipartito: para asignar repartidores a zonas, se agrega una fuente conectada a cada repartidor, una arista repartidor → zona por cada asignación permitida y cada zona al sumidero, todas con capacidad 1. Una unidad de flujo es una asignación, y el flujo puede reasignar a alguien cuando una elección inicial bloquea a otro.

// Edmonds-Karp sobre la red RESIDUAL: residual[u][v] -= delta; residual[v][u] += delta. constexpr int NODES{ 4 }; // 0 = S, 1 = A, 2 = B, 3 = T int edmondsKarp(int residual[NODES][NODES], const int source, const int sink) { int total{ 0 }; while (true) { int parent[NODES]{ -2, -2, -2, -2 }; int queue[NODES]{}; int head{ 0 }; int tail{ 0 }; parent[source] = -1; queue[tail++] = source; while (head < tail && parent[sink] == -2) // BFS: el camino con menos aristas { const int current{ queue[head++] }; for (int next{ 0 }; next < NODES; ++next) { if (parent[next] == -2 && residual[current][next] > 0) { parent[next] = current; queue[tail++] = next; } } } if (parent[sink] == -2) { return total; // T inalcanzable: flujo máximo } int delta{ INFINITE }; for (int node{ sink }; node != source; node = parent[node]) { delta = (residual[parent[node]][node] < delta) ? residual[parent[node]][node] : delta; } for (int node{ sink }; node != source; node = parent[node]) { residual[parent[node]][node] -= delta; // se gasta capacidad residual[node][parent[node]] += delta; // aparece la posibilidad de cancelar } total += delta; } }
